# TensorRT export/build extras (GPU only). Layers on top of requirements.txt,
# which already brings CUDA-enabled torch — used both to build engines
# (trt_export) and, together with torch, to run them (trt_infer) without any
# pycuda / cuda-python dependency (device buffers + stream are managed via torch).
#
# Pick the wheel matching the CUDA major of the installed torch build:
#   torch cu12.x  -> tensorrt-cu12   |   torch cu13.x -> tensorrt-cu13
# The bare `tensorrt` meta-package resolves to a CUDA-specific wheel; pin the
# `-cuNN` variant if the resolver picks the wrong one for your torch build.
# Pinned exact (not just major/minor): a TensorRT *engine* plan only
# deserializes on the runtime version that built it (see trt_infer/session.py),
# so letting this float across image rebuilds silently strands any cached
# .engine artifact (e.g. models/people/best_ckpt.engine) that was built on an
# older resolve. Bump this deliberately, and rebuild every cached engine in
# lockstep, rather than letting pip pick a new version on its own.
# THIS VERSION IS ALSO PINNED IN buildnode/requirements.txt and the two must
# match: a build node compiles engines this stack then loads, so a node on a
# different runtime produces bundles that cannot be deserialized here. Bump both
# together (see chachkalica/docs/build-nodes.md).
-r requirements.txt
# 11.1.0.106 to match nvcr.io/nvidia/tensorrt:26.07-py3 — the newest NGC
# TensorRT container tag that actually exists (26.08/26.09 don't, and there is
# no NGC image at all for 11.2.1.2 as of 2026-08-07). Both watchroom
# deployments' gpu-inference images pin TensorRT via that base image tag (see
# their docker/Dockerfile.gpu), so this has to track it exactly rather than
# floating ahead on whatever pip has.
tensorrt==11.1.0.106
# Graph surgery to append the EfficientNMS_TRT plugin node for archs whose baked
# NMS (retinanet, yolox) TensorRT can't compile directly.
onnx_graphsurgeon
# On TensorRT >= 11 (strongly-typed networks, no BuilderFlag.FP16) a real FP16
# engine needs the ONNX graph cast to fp16 first. trt_export/fp16_cast.py uses
# onnxruntime's float16 converter (already an onnx_export dep) and falls back to
# onnxconverter_common if present; without either it honestly builds FP32.
onnxruntime
# GPU utilization/memory sampling for inferlica/benchmark (NVIDIA's officially
# maintained wheel; provides the `pynvml` import). GPU-only, hence here and not
# in the base requirements.txt.
nvidia-ml-py
