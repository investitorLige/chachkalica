{% if autocast_rescued %}

FP16 here means ModelOpt AutoCast: this architecture's plain FP16 cast is on the safety floor (it fails the trained-checkpoint parity gate), but NVIDIA ModelOpt AutoCast's mixed FP32/FP16 graph reproduces the PyTorch model where that blanket cast destroys it — it keeps the numerically fragile decoder nodes in FP32 — so an FP16 build here goes through AutoCast automatically. Measured on real COCO weights over 24 images: mAP50 0.98–1.00 against PyTorch, versus 0.25–0.72 for the blanket cast, and about 2× faster than FP32. It is not a gate pass: neither this engine nor the FP32 one clears the strict per-detection gate against PyTorch (both miss one near-threshold detection), so the case for it is that aggregate agreement, not a green light. FP32 is still selectable — though for this architecture TensorRT's own FP32 engine is the less faithful of the two.
